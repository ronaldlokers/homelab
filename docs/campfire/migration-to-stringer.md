# Migrating the bots to `stringer`

A plan, not a record. Nothing here has been done yet.

## Why now

The bots are shipped as Python files mounted from a `configMapGenerator`. That
is the house pattern — ten apps use it — and it has been genuinely good: edit,
merge, and Flux has it running inside a minute, with no build step anywhere.

Two things changed.

**The renderer outgrew the pattern.** `chart.py` hand-rolls PNG encoding,
anti-aliasing, adaptive row filters and a baked glyph table, and `glyphs.py` is
a 57KB generated artefact regenerated by hand on a workstation with Pillow
installed. None of that is craft for its own sake — it exists because a
ConfigMap-mounted script cannot install anything. **The moment there is an
image, that constraint disappears, and most of that code stops earning its
keep.**

**Nothing tests the arithmetic.** The findings engine now makes claims about
health data: *"out of range on 11 of 14 days"*. There are 3,463 lines of Python
across the bots and no test suite. That is the actual risk here, not the repo
boundary.

## What moves, and what does not

| App | Lines | Posts to a room? | Disposition |
|---|---|---|---|
| `campfire-nightscout-digest` | ~1,000 | yes | **moves** — takes the renderer with it |
| `campfire-renovate-digest` | 246 | yes | **moves** — first mover |
| `campfire-alert-bridge` | 379 | yes | **moves** — exercises the long-running path |
| `campfire-status-bot` | 1,251 | yes | **stays** — reads Campfire's stream, holds an Anthropic key |
| `campfire-kube-actor` | — | no | **stays** — serves an API to the status bot; not a bot |
| `campfire-notify-check` | — | no | **stays** — checks notification config; not a bot |

Only four of the six actually post, and one of those four is genuinely
Campfire-coupled. Forcing `status-bot` through a room-agnostic seam would be
abstraction for its own sake.

**Homelab keeps everything Flux touches**: CronJobs, Deployments,
NetworkPolicies, Services, RBAC, SOPS Secrets, and both overlays. Per migrated
bot the manifest change is exactly two things — set `image:`, delete its
`configMapGenerator`.

## Language

TypeScript, and the renderer is **rebuilt rather than ported**.

- **Not Rust.** None of its advantages bind here. This is a CronJob that runs
  for two seconds a day. There is no throughput problem, no memory pressure and
  no binary-size constraint, and the real risk — statistical reasoning about
  health data — is not something the borrow checker has an opinion about.
- **Not Python, except by inertia.** The existing code works and is heavily
  commented. But the person maintaining this in two years thinks in TypeScript,
  and that is the whole argument.

**Rendering: hand-built SVG, rasterised by `@resvg/resvg-js`.** The counted rows
are `<rect>`s, the trace is a `<polyline>`, the findings are `<text>`. Fonts are
embedded in the image and referenced by name, so `bake_font.py`, `glyphs.py` and
the entire baked-type pipeline are deleted rather than translated. Expect ~200
lines of layout to replace ~1,000 of renderer.

`@resvg/resvg-js` publishes prebuilt binaries for both architectures this repo
runs on, in both libc flavours: `-linux-arm64-gnu` (production, Pi CM5) and
`-linux-x64-gnu` (staging, k3d on a Proxmox VM), with musl variants if the base
ever changes.

Satori was considered and rejected: it is a CSS engine for OG images, and this
is a data chart. Hand-built SVG is less magic and more controllable.

## Repository

`ronaldlokers/stringer` — a stringer is a freelance correspondent who files
reports from a beat they cover, which is exactly what six independent bots are.

```
stringer/
  src/
    desks/        the bots, each covering a beat: glucose, renovate, alerts
    press/        the renderer — SVG in, PNG out
    rounds.ts     Round: say(html), show(png, filename)
                  CampfireRound, NtfyRound, StdoutRound
  fonts/          embedded in the image, no baking step
  test/
    golden/       fixture fortnights and their expected findings
  Dockerfile
```

`ROOM_URL` selects the transport by scheme (`campfire+https://…`,
`ntfy+https://…`). `CAMPFIRE_URL` stays supported as a deprecated alias so the
Secrets can migrate one bot at a time.

## Phases

Each phase ships independently and is revertable on its own.

### 1. Skeleton and CI

Repo, TypeScript config, linting, `Dockerfile` on `node:22-bookworm-slim`, and
a multi-arch build publishing `linux/amd64` and `linux/arm64` to `ghcr.io`,
public.

**Both architectures are mandatory** — staging is amd64 and production is arm64,
and a single-arch image would pass in staging and fail on the Pis.

**`tzdata` is installed explicitly**, never assumed. Every day boundary this
program computes is a local midnight in `Europe/Amsterdam`, and a missing zone
database does not crash — it silently falls back to UTC and reports the wrong
day. A test asserts that a DST changeover produces a 23-hour day.

*Exit:* a hello-world image runs on both clusters, and the DST test passes
inside it.

### 2. Findings engine, with golden tests

Port the statistics before anything else, and prove it: capture the current
Python output for a set of fixture fortnights, commit those as golden files, and
make the TypeScript reproduce them exactly.

Cover: finding selection and priority order, the outlier comparisons,
day-splitting across DST boundaries, `sheet_for` weekday logic, degenerate days
(flat, sparse, absent), and PNG chunk and CRC validity.

**This phase is the justification for the whole exercise.** If it slips,
everything after it is moving code around.

*Exit:* TypeScript findings byte-identical to Python across every fixture.

### 3. Renderer

**Done.** Both sheets are rebuilt as SVG in `src/press/`, rasterised by resvg,
and DESIGN.md moved with them.

The metrics were the one thing that could not be thrown away: the sheet wraps a
computed sentence at 56px across a fixed measure, and an estimate of average
character width put the headline on a third line and into the rows. The
per-character advances from the Python's baked glyph tables are kept in
`src/press/metrics.ts`.

The port also reproduced a live bug exactly — findings growing down into the
figures whenever the first one wrapped — which is how it was found.

DESIGN.md moved to stringer with the renderer it describes.
It documents a visual system: a palette, a type scale, a composition and a list
of refusals. All of that is a property of the thing that draws, and after this
phase the thing that draws lives there. It gets rescoped on the way — it
currently says "the campfire namespace", which stopped being true the moment
the transports went room-agnostic; what it actually describes is what stringer
draws, whichever room the copy goes out to.

It did not move earlier. Until the renderer was there, a specification sitting
in a repository that contains no implementation of it is a document nobody is
reading while they edit the code it governs.

**PRODUCT.md stays here.** It is not about the drawing — it is about the
reader, the room, the cadence, the attachment box Campfire actually gives an
image, and the cluster that runs the thing at 07:00. That is homelab's business
and stays beside the manifests. Stringer's README covers what stringer is.

*Exit:* met — fortnight and daily sheets match the approved renders, and
[DESIGN.md](https://github.com/ronaldlokers/stringer/blob/main/DESIGN.md) is in
stringer describing them.

### 4. First mover: `renovate-digest`

246 lines, no health data, and if it breaks for a day the cost is one missing
Renovate summary. Proves image build → ghcr → Flux → Renovate bumping the tag,
end to end, on something that does not matter.

**Done.** Output was checked against the Python on the live repository before
the swap — ten open pull requests, two flagged, byte-identical HTML.

### 5. `glucose`

**Done.** The valuable one, and it took more than itself: `chart.py`,
`glyphs.py`, `bake_font.py`, the golden fixtures and homelab's whole test suite
were all glucose, so they went too. The hand-baked font pipeline is gone from
the repository entirely.

Verified in the cluster before the swap rather than over a week — the same
image, against the same Nightscout, reported the same 280 readings and 13 days
of history as the Python, and posted one sheet into the room beside the
Python's for the same day.

### 6. `alerts` — withdrawn

**Not moving, and the plan was wrong to assume it could.** It was listed here as
"a Deployment rather than a CronJob", as though the shape of the workload were
the interesting difference. It is not.

The bridge amends the message that announced an alert rather than posting a
second one, so the room shows the current state instead of a log of states. That
is not decoration — it is built on a Campfire implementation detail:
`MessagesController#update` does not call `room.receive`, so **an edit notifies
nobody**. The whole delivery rule falls out of that one fact:

  * a fingerprint that was not firing before  → POST, so it pushes
  * only resolutions since last time          → PATCH, silently
  * the whole group resolved                  → PATCH, then forget it

It also PATCHes `{destination}/{message_id}`, recovers that id from the
`Location` header of its own POST, and needs a Campfire feature
(basecamp/once-campfire#239) that the image is pinned to a digest for.

A `Round` is `say` and `show`. It cannot express "amend the thing you said
before, quietly", and neither can ntfy or most other destinations. Porting this
room-agnostically means one of two things, and both are worse than leaving it:

  * **drop the amending** — the room becomes a log of firing and resolved
    states, and every resolution pushes a notification to a phone; or
  * **add an `amend` capability to `Round`** that exactly one transport can
    implement — an abstraction shaped by a single implementation, which is the
    thing the seam exists to avoid.

This is the same test `status-bot` failed, and it fails it harder: that one
*reads* Campfire's stream, this one uses Campfire's editing semantics as a
design primitive. A bot that only needs somewhere to post is portable. A bot
that needs Campfire to behave like Campfire is not, and pretending otherwise
buys nothing.

## Where this ends

The migration is finished at phase 5, and the line it drew is the honest one:
the two bots that only ever needed somewhere to post — `glucose` and
`renovate` — moved. The four that use Campfire as more than a destination, or
are not bots at all, stayed:

| App | Why it stayed |
|---|---|
| `campfire-alert-bridge` | amends its own messages; relies on edits not notifying |
| `campfire-status-bot` | reads Campfire's message stream, holds an Anthropic key |
| `campfire-kube-actor` | serves an API to the status bot; not a bot |
| `campfire-notify-check` | checks notification config; not a bot |

That is a better outcome than moving all six. "Campfire bots" turned out to name
two different things, and only one of them was ever about the room.

## How homelab consumes it

Nothing new in homelab. Image tags in CronJobs and Deployments are already
picked up by Renovate's `kubernetes` manager, so version bumps arrive as PRs
exactly like every other image here.

```yaml
# before
image: python:3.13-alpine
command: ["python3", "/opt/digest/nightscout-digest.py"]
volumeMounts: [{ name: script, mountPath: /opt/digest }]

# after
image: ghcr.io/ronaldlokers/stringer:v1.2.0
args: ["glucose"]
```

## Rollback

Per phase, and cheap at every point: revert the manifest commit and the
`configMapGenerator` comes straight back, because homelab keeps the manifests
and the Python is still in git history. No phase deletes the old path until the
new one has run in production for a week.

## Risks

- **Statistics drift during the port.** Mitigated by phase 2 being golden-tested
  against the current implementation rather than written fresh.
- **Wall-clock minutes, on the two days that are not 24 hours long.** The Python
  computes a reading's position in its day as `when - midnight`, which reads
  like elapsed time and is not: Python ignores the offset when both datetimes
  share a tzinfo, so it is wall clock. Hours therefore mean the same thing on
  every day, which is what makes "the 08:00 hour ran out of range on 12 of 14
  days" a comparison rather than a coincidence, and the hour that happens twice
  lands in its slot twice. JavaScript has no equivalent shortcut and will
  subtract instants, so the port has to take the local hour and minute from the
  formatter rather than differencing timestamps. Getting this wrong shifts every
  reading after a changeover by an hour and pushes some off the sheet entirely.
- **Native binary on arm64 musl.** Prebuilt binaries exist, but this is the one
  assumption worth proving in phase 1 rather than discovering in phase 5.
- **The loop gets slower.** Today: edit, merge, visible in a minute. After: edit,
  CI build, bump tag, Flux. This is the real cost, and it is why the split waits
  until the design has settled.
- **Six-week half-migrated state.** Two bots on images and two on ConfigMaps is
  the normal condition during a strangler migration, but it does mean two ways
  of doing the same thing while it lasts.

## Decisions

1. **Registry** — `ghcr.io`, **public**. No `imagePullSecret` in either cluster.
2. **Base image** — **`node:22-bookworm-slim`**, not Alpine. Alpine's only real
   advantage is ~35MB, which is nothing on three Pis with NVMe, and musl costs
   the better-trodden arm64 path, the more widely exercised native binaries, and
   an easy-to-forget `apk add tzdata` guarding a bug that would silently report
   the wrong day.
3. **No npm publish.** The container image is the only artefact. Publishing a
   package with one consumer would be for its own sake.

## Out of scope

`campfire-status-bot`, `campfire-kube-actor` and `campfire-notify-check` stay in
homelab as Python ConfigMaps. The four non-campfire ConfigMap scripts
(`gatus`, `netpol-check`, `secret-refs-check`, `recovery-source-check`) are not
touched.
